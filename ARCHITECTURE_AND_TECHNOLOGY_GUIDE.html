3. Backend & API Architecture (Next.js Server)

The backend runs directly inside the Next.js unified framework using Route Handlers located under src/app/api/. It connects to PostgreSQL via Prisma ORM with an integrated local database abstraction layer (DatabaseStore) for bulletproof failover.

Key Technologies & Libraries

  • Next.js Route Handlers (HTTP Server): Supports standard HTTP verbs (GET, POST, PATCH, PUT, DELETE) with structured streaming and JSON responses.
  • Prisma ORM (v6.4.1): Type-safe database client communicating with PostgreSQL on port 5432. Auto-generates TypeScript types matching schema models.
  • Jose (v6.2.13) & Bcryptjs (v3.0.3): Secure JWT generation, verification, and salted password hashing without native binary dependencies.
  • Nodemailer (v10.2.1): SMTP email delivery engine for account registration, order confirmation receipts, and low-stock administrative alerts.
  • AWS SDK S3 Client (v3.1158.0): Cloud object storage integration for product imagery, variant photos, and marketing banner assets.
  • Expo Push API: HTTP/2 push notification dispatcher delivering real-time push alerts to mobile devices via https://exp.host/--/api/v2/push/send.

API Response Convention

All endpoints utilize a strict, consistent JSON envelope format for predictability:

{ "success": true, "data": [...], "message": "Operation successful." } (Success)
{ "success": false, "error": "Descriptive error message.", "status": 400 } (Error)

6. Step-by-Step Data Flow & Execution Workflows

A. Mobile Add to Cart & Checkout Flow

1. User interaction: Customer views a product card or details page (app/products/[id].tsx) and taps Add to Cart.
2. Store & Animation: useCartStore.addToCart() is triggered. Button enters a spinner loading state (ActivityIndicator).
3. Toast Dispatch: useToastStore.showToast() displays a floating pill: "Added to Cart! 🛍️" with a "View Cart →" shortcut.
4. API Synchronization: Axios dispatches POST /api/cart to Next.js on port 3001. Next.js verifies current stock in PostgreSQL and updates cart.
5. Badge Sync: Root tab bar counter in app/(tabs)/_layout.tsx updates immediately without screen re-render.

B. Push Notification Broadcast Flow

1. Mobile Device Registration: When the mobile app starts, registerForPushNotifications() calls Expo Push Service to get an ExponentPushToken and sends it to POST /api/notifications/register.
2. Admin Composition: Admin opens /admin/marketing/notifications in web browser, enters title/message, selects emoji and action link, and verifies the live phone preview.
3. Master Switch Validation: System checks settings.notificationsEnabled. If ON, proceeds; if OFF, alerts admin that push is paused.
4. Expo Dispatch: Backend compiles chunks of push tokens and posts to Expo push server (https://exp.host/--/api/v2/push/send).
5. Native Reception: Customer device receives the notification, plays sound, displays top system alert, and when tapped opens the targeted deep link (e.g. /(tabs)/deals).

C. Database Dual-Persistence (Postgres + Local Store)

1. Primary Storage: PostgreSQL running in Docker (container: ecommerce_postgres, port: 5432) accessed via Prisma ORM.
2. High Availability Layer: DatabaseStore in src/core/db/store.ts manages in-memory caching and persistent local JSON synchronization so the entire app operates smoothly even during database migrations or network restarts.
